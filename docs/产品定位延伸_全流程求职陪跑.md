# 产品定位延伸：从「AI 模拟面试官」到「全流程求职陪跑平台」（v7.3）

> 起因是项目复盘时的一个直感：「功能是不是太多且太独立了，给人一种很混乱的感觉」。本文先回答这个判断，再给出**不改任何现有功能**的解法——向上延伸产品定位，让所有功能在一条主线下各有归属。

> **v7.5 范围收缩更新**：本方案（v7.3）中的"连机会"步骤（报告分享 + 招聘者收件箱）与"连接"导航分组，经复盘判定为与"面向求职者"定位冲突的强加第二端（画蛇添足），已在 v7.5 删除——产品回归**五步旅程 + 求职者单端**，认证与资源归属保留。取舍理由见 `docs/week10_范围收缩_回归求职者单端_需求.md` 与 CHARTER **DC-08**。下文中标注为 v7.3 的内容是当时的决策记录，现行规范以五步版本为准。

---

## 一、诊断结论：混乱感从哪来

对 v7.2 全量盘点（15 个功能域 / 11 个导航入口 / 后端 44 个模块 1.4 万行 / docs 34 篇）后的事实：

**「功能太多」成立，但「太独立、各写各的」不成立。** 代码层面的统一度其实不低：

- 全站单 SPA，11 个入口走统一侧边栏；招聘者登录后面板按身份显隐联动；
- 所有模块共用 `api.js` 请求层、`utils.js`（toast/确认/空状态）、`tokens.css` 设计令牌，无页面自建；
- 功能间有真实数据链路：面试 → 报告 → 分享 → 招聘者收件箱；市场 → Gap 分析 → 职业规划；面试 → 长期记忆回注入。

混乱感的真实来源是**叙事与结构层**，而非代码复用层：

| 来源 | 证据 |
|---|---|
| 产品边界失控（主因） | 一个月内七期竞品借鉴搬入 50+ 项功能，产品名仍叫「模拟面试官」，题库/市场/规划/记忆看起来像拼在同一个壳里的多个小产品 |
| 视觉体系高频推翻 | 一个月 4 轮主题重构，三代 UI 规格文档并存，历史层积造成"不统一"观感 |
| 工程结构性遗留 | main.py 65 条路由未拆分；style.css/dark.css 遗留双轨；根目录临时文件反复出现 |
| 文档与现实漂移 | README 结构树缺 6 个前端文件；版本号/用例数三处口径不一；docs 有只评估未落地的方案 |

**结论**：解法不是砍功能、不是重写代码，而是**把定位向上延伸一层**——产品不再只是"模拟面试官"，而是覆盖求职全流程的陪跑平台；面试只是其中一步。这样每个既有功能都获得叙事位置，混乱感从根上消解。

## 二、新定位（v7.3 起）

- **产品名**：AI 求职陪跑（平台）
- **一句话定位**：从职业定位到拿 Offer 的全流程 AI 求职陪跑。
- **关系**：与「AI 模拟面试官与职业规划」是**包含关系**——原命题的"诊断 + 规划"两条产品线降为主线中的两步（能力诊断 / 发展路径），命题本身不废，向上生长。

### 五步主线（v7.5 起；v7.3 曾含第 6 步"连机会"，已被范围收缩取消。v8.1 术语统一为专业评测语系，步骤改名、结构不变，见 CHARTER DC-09）

```
职业定位 ──→ 简历准备 ──→ 面试演练 ──→ 能力诊断 ──→ 发展路径
市场数据       简历库       模拟面试      综合报告      职业规划
岗位库                      题　库       长期记忆
                            历史记录
```

> v8.1 更名对照：定方向→职业定位、备弹药→简历准备、演练→面试演练、诊弱点→能力诊断、定规划→发展路径。

功能映射（**全部为既有功能，零增删**）：

| 旅程步骤 | 承载功能（既有） | 叙事角色 |
|---|---|---|
| ① 职业定位 | 市场数据（采集/检索/对比）、岗位库 | 看行情、选岗位，知道往哪走 |
| ② 简历准备 | 简历库 | 简历是面试与 Gap 分析的基础素材 |
| ③ 面试演练 | 模拟面试（多轮/语音/公司风格）、题库、历史记录 | 主训练场，产品的心脏 |
| ④ 能力诊断 | 综合报告（五维诊断/雷达图/逐题拆解）、长期记忆图谱 | 演完必诊，薄弱点跨场沉淀 |
| ⑤ 发展路径 | 职业规划（时间轴路径/Gap 分析） | 薄弱点变路线图 |
