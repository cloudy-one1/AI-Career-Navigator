# Week1 需求文档：数据支撑 / 技能匹配模块（data_support）

> ⚠️ 模块定位：非必需模块。CODEBUDDY 规范明确——需先做最小实验验证价值后再决定是否正式开发。

## 一、模块目标

根据 JD 关键词，从静态岗位技能数据集中匹配最相关的岗位类型，并推荐该岗位的核心技能要求，作为回答质量诊断时的"岗位能力参照"。

## 二、当前实现状态（骨架已就绪）

文件：`backend/data_support.py` + `backend/skills_data.json`：

- `skills_data.json`：内置 8 类岗位（后端/前端/数据分析/算法工程/产品经理/测试开发/运维DevOps）+ `通用`，每类含 `keywords` 与 `skills` 列表。
- `_load_skills()`：启动时按 `config.SKILLS_DATA_PATH` 加载一次（带缓存）。
- `match_skills(jd_keywords)`：遍历各岗位，用关键词**子串包含**统计命中数 `hits`，取前 3 名（按 `match_count` 降序），并固定追加"通用"技能。
- `get_all_positions()`：返回所有非通用岗位类型。

## 三、技术方案

- **静态数据集 + 规则匹配**：不调用 LLM，纯本地 JSON + 字符串匹配，零延迟、零成本。
- **命中率排序**：`sum(1 for kw in jd_keywords if kw.lower() in " ".join(pos_keywords).lower())`，按命中数排序取 Top3。
- **降级策略**：始终附上"通用"技能，保证即使无强匹配也有兜底输出。

## 四、涉及的知识点

- JSON 静态数据的加载、缓存与路径管理（`config`）。
- 字符串匹配 / 包含判断与大小写归一化。
- 简单排序与 TopN 截断。
- 模块解耦：技能数据外部化到 JSON，便于非开发人员维护。

## 五、待完善 / 优化点（需先做最小实验）

- [ ] **价值验证（优先）**：先用一小组真实 JD 跑 `match_skills`，确认匹配结果对诊断"岗位相关性"维度有实质增益；无增益则建议搁置本模块。
- [ ] 匹配算法粗糙：当前为子串包含，易误命中（如 "Go" 命中 "Google"）。可升级为分词 + 编辑距离 / 关键词精确匹配。
- [ ] 数据集覆盖有限（仅 8 类），需补充岗位或改为可配置外部维护。
- [ ] 与诊断引擎的集成方式未定：是作为 `jd_text` 旁路提示，还是直接注入诊断 prompt 的岗位能力参照。
- [ ] 注意范围纪律：本模块属于"非必需"，任何扩展（如联网拉取岗位数据、动态技能图谱）均需用户批准。
