# 三个模块差距分析与阶段结论

> 日期：2026-07-31
> 性质：纯分析文档（无代码实现）
> 背景：对标 MockMate 的可对齐项，经差距分析 + 第一性原理评估后形成的阶段决策记录。

## 一、背景与目标

v2.5 已完成岗位画像研究、诊断反馈、引擎模块化拆分。对标 MockMate 后仍余三项可对齐模块：

1. 用户认证系统（登录 / 多用户隔离）
2. 语音交互升级（浏览器 Web Speech API → 云端 TTS/STT）
3. HTTPS / 局域网安全访问

本任务为**仅分析差距**，不实现代码。目标：明确三项与"产品级"的差距，并从第一性原理判断其在当前课程项目阶段是否必要。

---

## 二、现状证据（v2.5 代码实测）

| 模块 | 现状 | 证据位置 |
|------|------|---------|
| 用户认证 | 无任何 auth/token/login；会话仅 `session_id=uuid4().hex[:12]`；无 user 概念；CORS `allow_origins=["*"]` | `backend/main.py`、`backend/db.py` |
| 语音交互 | 仅浏览器原生 Web Speech API（TTS=`SpeechSynthesis`、STT=`SpeechRecognition`），纯前端、无后端、依赖 Chromium | `frontend/js/voice.js` |
| HTTPS | `uvicorn --host 0.0.0.0 --port 8000` 纯 HTTP；无 TLS、无反向代理；前端硬编码 `http://`/`ws://` | `run.py`、`frontend/js/api.js` |

## 三、差距对照表

### 1. 用户认证系统

| 维度 | 当前 | 目标（MockMate 级） |
|------|------|---------------------|
| 身份 | 无用户 | 注册 / 登录，用户隔离 |
| 鉴权 | 无 | Token（JWT/Session）校验全部 HTTP + WS |
| 数据隔离 | 全局共享 | 会话 / 报告 / 题库按 `user_id` 过滤 |
| 凭证存储 | 无 | 密码哈希（bcrypt）+ Salt |
| CORS | `*` | 限定前端域名 |

### 2. 语音交互升级

| 维度 | 当前 | 目标 |
|------|------|------|
| TTS 引擎 | 浏览器内置 | 云端 TTS（Azure / 阿里云 / 火山 / OpenAI），稳定中文音色 |
| STT 引擎 | 浏览器内置 | 云端 ASR，支持长音频、端点检测 |
| 后端 | 无 | 新增 `/api/tts`、`/api/stt` 转发音频 |
| 降级策略 | 无 | 云端失败回退浏览器原生 |
| 跨浏览器 | 仅 Chromium | 全浏览器可用 |

### 3. HTTPS / 局域网安全访问

| 维度 | 当前 | 目标 |
|------|------|------|
| 传输 | HTTP 明文 | HTTPS（TLS） |
| WS | `ws://` | `wss://` |
| 局域网部署 | 直接暴露 uvicorn | Nginx / Caddy 反代 + 证书 |
| 安全头 | 无 | HSTS / CSP 等 |

## 四、第一性原理评估

**项目第一性原理**：核心价值 = 诊断候选人的回答质量（STAR 完整性 / 量化程度 / 逻辑连贯性 / 岗位相关性 / 专业深度）。出题是诊断质量的上限杠杆——问题围绕诊断维度设计、诊断结果反哺出题策略，二者构成"出题—诊断"闭环。本系统与题库型 / 逼真型面试 App 的差异不在"不出题"，而在出题服务于诊断闭环。注：原"不是像不像面试官"表述曾将出题与诊断对立，已被代码分配证伪（见 `docs/week6_核心价值重述_需求.md`），此处重写为更准确的说法。

用此标尺衡量：

| 模块 | 对诊断内核的贡献 | 本质 | 结论 |
|------|------|------|------|
| 用户认证 | 0 | 多用户隔离 + 权限，不改变单次诊断质量 | **不必要**，属提前负债（仅多租户 / SaaS 阶段需要） |
| 语音升级 | 0 | 输入/输出通道体验，不影响诊断准不准 | **非必要**，可选增强 |
| HTTPS | 0（本地）/ 低（部署） | 传输加密；本地回环场景无实际风险 | **本地不必要**，部署/公网访问时才必要 |

三模块均不放大"诊断更好"这一核心价值，而是让产品"更完整 / 更像个系统"，属于**产品化（多用户、上云、生产部署）阶段**事项，非当前"本地单机诊断工具"阶段必要项。

**更值得投入的方向**（直接放大核心价值）：
- 诊断维度权重按 JD 动态化
- 追问与诊断流式合并（文档"已知限制"已列）
- 雷达图实时更新
- 弱项自动追加针对性题

---

## 五、阶段结论

> **用户认证系统、语音升级（云端 TTS/STT）、HTTPS / 局域网安全访问：作为未来优化方向保留，在课程项目（本地单机诊断工具）阶段不做实现。**

理由：
1. 三者均不提升诊断内核质量；
2. 实现成本高（认证贯穿 DB/API/WS/前端，语音需外部密钥，HTTPS 需部署改造）而当前阶段收益低；
3. 原范围纪律已将其列为"ROI 不足 / 部署阶段再考虑"，本次第一性原理评估佐证该结论。

若未来产品演进至多用户共享平台或需公网部署，再重新评估并按范围纪律逐项批准。
