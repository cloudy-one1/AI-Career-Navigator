# Week6 — 安全能力诚实降调与局限披露

> 本文档记录一次"批判性纠偏"：用户在审计中指出本项目的"生产级加固 / 5 层安全体系"等定性存在夸大，并暴露了 .env 含真实 Key、无认证、双 Agent 成本与 SQLite 扩展性等已知局限。本次整改的目标是**让文档与代码对自身安全能力做出诚实定性**，而非增强防护强度。

## 一、模块目标

1. 把 README / CODEBUDDY.md 中"生产级加固""5 层安全体系""生产级容器镜像"等夸大表述，降调为课程项目级、启发式的诚实定性。
2. 净化 `.env`：真实 DeepSeek API Key 与本地绝对路径改为占位符，防止再次打包泄露。
3. 降低 `security.py` 对正常面试回答的误伤（收窄正则 + 歧义句式降级为软告警）。
4. 在 README / CODEBUDDY.md 新增"已知局限与架构取舍"章节，诚实披露无认证、双 Agent 成本、SQLite 扩展性、测试偏纯函数等核心局限，并附可选演进方向（不实现）。

## 二、技术方案

- **文案层面**：移除"生产级""5 层安全体系"等标签，统一为"启发式内容检查（课程项目级，非安全边界）"。
- **配置层面**：`.env` 不再含真实密钥与本地路径，与 `.env.example` 对齐为占位符 / 相对路径。
- **代码层面**：`security.py` 的注入检测拆分为 `INJECTION_PATTERNS_HARD`（高置信攻击句式，命中即拒）与 `INJECTION_PATTERNS_SOFT`（"从现在开始""你必须输出"等歧义句式，仅 `logger.warning`，不阻断）。`check_input` 签名与返回保持不变，仅软告警不计入 `is_safe=False`。`full_check(text, history)` 签名不变，调用方 `main.py` 无感。
- **测试层面**：保留既有拦截用例，新增 `TestNoFalsePositive` 回归用例，证明用户指出的误伤句式（"从现在开始我负责这个模块""我要求团队必须输出周报"等）现可正常通过。
- **文档层面**：新增"已知局限与架构取舍"章节（README）+ "已知局限（诚实披露）"（CODEBUDDY.md）。

## 三、修改记录（2026-08-13）

### 原方案的问题本质

v3.1 把**外围工程措施**（日志轮转、slowapi 限流、HTTP 安全响应头、请求体大小限制）与**关键词正则过滤**打包命名为"生产级加固""5 层安全体系"。其中：

- "5 层安全防护"实质是 **4 类基于正则/关键词的启发式匹配**（输入注入、输出泄露、状态校验、记忆防污染），本质是"内容护栏"，不是安全边界。它有两个结构性缺陷：
  - **假阴性**：换说法、错别字、同义词、中英混杂、Base64/拼音/编码变形即可绕过；
  - **假阳性**：部分模式与正常业务语言高度重叠，会误伤真实回答（如"从现在开始我负责这个模块"命中 `从\s*现在\s*开始`）。
- "生产级"与"无认证/授权"在逻辑上自相矛盾：session_id 是随机串，只能防猜测，不是访问控制；任何拿到链接的人都能读他人简历/诊断/报告。

此外，打包上传的 zip 中 `.env` 含一个**真实 DeepSeek API Key** 与**本地绝对路径**（`f:/Desktop/project1-enhanced/data.db`），虽被 `.gitignore` 排除、未进 git 历史，但已离开本地环境，存在密钥泄露风险。

### 用户的批判性判断点

- 用户明确指出"生产级加固"属于**定性夸大**：它防的是最业余的注入尝试，防不住任何认真的攻击者；README 不应同时喊"生产级"和"无认证"两个互相矛盾的口号。
- 用户用**具体误伤样例**举证正则缺陷，要求"诚实定性"而非"增强强度"。
- 用户对双 Agent 架构提出**成本性质疑**：每题 2 次 LLM 调用是真实代价，"优于单 Agent"缺乏量化对比实验，属先验架构偏好。
- 用户肯定 SQLite 扩展性上限"作者已点破"的诚实披露，但指出"生产级加固话术"主要停留在外围，未触及核心并发/扩展问题。
- 用户纠正"50 个测试用例"的认知偏差：覆盖的是确定性逻辑，核心诊断质量（准确性/追问抓最弱维度/评分稳定性）依赖 LLM，单测难以验证，故"用例数"≠"核心功能被验证"。

### 修改后的方案

- 文档全部降调，新增"已知局限与架构取舍"章节，把上述 6 项局限与可选演进方向一并公开。
- `.env` 净化并加注释提醒。
- `security.py` 收窄误伤正则、歧义项降级软告警，模块与注释诚实化为"启发式内容检查，非安全边界"，并显式标注"认真绕过者仍可规避"。
- 不实现认证、不换数据库、不做单 Agent 对比实验（属"未来优化方向"，经第一性原理评估不提升诊断内核质量）。

## 四、批判性思维摘录 [批判性思维]

- **定性纠偏**：用户推翻了"生产级加固 / 5 层安全体系"的工程叙事，指出关键词过滤 ≠ 安全边界；判断依据：安全工程的第一性原理——客户端启发式无法构成可信边界，真正的安全来自认证/授权与服务端隔离。
- **反指标意识**：用户拒绝用"测试数量"替代"测试有效性"，点破"50 用例通过"的指标幻觉；这是对被广泛滥用的"覆盖率即质量"叙事的批判。
- **范围克制**：用户对双 Agent 成本、SQLite 扩展性的质疑停留在"披露 + 给方向"，未要求立即实现，符合"课程项目阶段不做上云/产品化"的既定取舍纪律。
- **安全卫生**：用户将"打包含真实 Key 的 .env"定性为操作习惯问题（应在提交前删 .env 或用占位符），并要求立即吊销 Key——这是把"项目安全"从代码层面扩展到"交付卫生"层面的纠偏。
