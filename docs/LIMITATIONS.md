# 已知局限与架构取舍

> 本文件自 README 迁入（v8.3.2 文档标准化）。本系统定位为**课程项目**，
> 以下局限是已知的、刻意的取舍，**不是待修复的 bug**。
>
> 更精简的约束与决策记录见 [CHARTER.md](../CHARTER.md)（含决策记录卡 DC-01 ~ DC-11）。

| 局限 | 说明 | 可选演进方向（未实现） |
|------|------|------------------------|
| **无认证/授权**（v8.3 起为设计前提） | v7.0 曾提供认证层与资源归属（DC-06），v8.3 经 DC-10 整体下线；本系统定位单用户本地工具，全站免登录 | 若未来要部署给多人/外部访问，需重建认证（代价见 DC-10） |
| **WebSocket 无连接身份校验**（v8.3 起为设计前提） | 握手仅校验会话是否存在（`close(4000)`），不校验身份；v8.3 前曾校验 token 失败 `close(4001)`，已随认证下线移除 | 同上 |
| **无断点续答** | v7.0 落库了流程位置与答题数，但进程重启后**不能**从 DB 重建会话续答；已答题与报告不丢，进行中的那道题会丢。注：`_mark_flow()` 在 v7.3.1 之前 5 处漏写 `await`，流程位置实际从未真正写入（仅产生静默 RuntimeWarning），v7.3.1 已修复 | 序列化整个 `InterviewSession`（成本高，暂不做） |
| **全局单例可变状态** | `llm_client`/`diagnosis_engine` 为模块级单例，被所有会话共享、无按会话隔离；多后端高频切换或并发导入下内部 provider 状态存在理论竞态 | 引入按会话隔离的客户端实例或请求作用域依赖（课程项目阶段仅文档披露，不做隔离） |
| **双 Agent 成本（v8.6 已可调节）** | Diagnostician + Rewriter 每题至少 2 次 LLM 调用，流式下延迟与 token 成本翻倍。v8.6 起 `AUTO_REWRITE=false` 可让改写改为**按需生成**（诊断出分后由前端请求），省掉每题一次完整往返的**感知延迟**（不省 token） | 做单 Agent + 结构化输出（JSON）的对比实验，量化"分 vs 合"的质量/成本权衡后再决策 |
| **追问补评依赖 LLM（v8.6 新增能力的新增局限）** | v8.6 前追问补充"只进报告、不进分数"（已披露的评分盲区）；v8.6 起补答会触发一次增量重评，五维分/总分/最弱维度全部更新，首评原分保留在 `pre_follow_up`。但补评仍是一次 LLM 调用：**分数可被补评下调也可能上调**，且模型若把"多说几句"当成"答得更好"，补评会退化成送分机制（prompt 已加显式约束，`reassessment_stats.avg_delta` 可观测该倾向）；LLM 失败时静默退回首评 | 用人工标注样本统计补评前后与人工判断的一致率；`avg_delta` 长期显著为正时收紧 prompt 约束 |
| **思考时长来自前端上报（v8.6 降级为可交叉校验）** | 前端从"题目渲染完成"起算并随 `answer` 上报，后端仅做 0–600s 合法性归零；页面切后台、设备休眠、组件重渲染导致计时起点被重置都会让该值失真。v8.6 起服务端额外记录"推题 → 收到回答"的墙钟差，前端上报值不可能大于它，违反时以服务端值为准并标注 `thinking_seconds_anomalous` | 服务端无法独立算出"用户真正开始思考"的时刻，墙钟差只是上界；要更准需前端上报渲染完成事件由服务端打时间戳 |
| **模型调用单点故障（已缓解）** | 原仅单模型，任一 provider 故障即硬失败；v4.3 起支持 `LLM_FALLBACK_CHAIN` 优雅降级，主模型失败自动切备用模型，调用方零改动、不影响双 Agent 诊断客观性 | 仍建议为备用 provider 配置独立密钥以保障可用性 |
| **SQLite 扩展性** | 单文件数据库；多 Worker 下 WebSocket 需 sticky session，水平扩展受限 | 换异步 Postgres / 引入连接池；或改用内存态 + 持久化分离 |
| **内容护栏可被绕过** | 见上节，正则过滤防不住认真攻击者 | 见上节演进方向 |
| **测试偏纯函数** | 确定性逻辑（权重/Schema/评分修正）覆盖充分；但**诊断准确性、追问是否抓最弱维度、评分稳定性**依赖 LLM 输出，单测难以验证 | **已实现（v7.0.3）**：黄金样本回归（20 条人工标注样本 × 确定性断言）+ live-LLM 抽检（默认 deselect），首次把"诊断有效性"纳入可观测范围 |
| **证据检索为本地启发式** | v5.0 简历证据检索是本地关键词 + 优先级加权，非语义向量检索；中文分词粒度受限，同义/模糊表述可能漏命中，仅作证据提示不替代向量库；可调参数为代码级常量未下沉 `.env` | 引入轻量向量库（如 sqlite-vec / faiss）做语义召回；参数下沉配置 |
| **语音为半双工、音频不落库（v7.4 现状）** | 云端 ASR 是请求-响应协议：整段录完才识别，不能边说边出字；VAD 只判断「何时停」，**不做端点检测、不裁剪音频**（开头等待与结尾 2.5s 静音仍在上送音频里）；预滚校准在「开麦瞬间就说话」时会高估底噪；报告只存转写文本，**不存原始音频与 ASR 置信度**，复盘时无法判断某句是否转写幻觉；转写失败即丢弃录音，无重试 | 端点检测裁剪尾部静音；音频随会话落库 + 转写置信度入报告；失败后本地暂存支持重试 |
| **语音端点无鉴权（v7.4 已知）** | `/api/voice/tts`、`/api/voice/asr` 按设计公开（认证已于 v8.3 下线，见 DC-10），匿名可调；唯一防线是 `RATE_LIMIT_VOICE=20/min`（按 IP 计数） | 若部署到不可信网络，应给 voice 路由加访问控制 |
| **知识库为关键词检索且未接入业务流** | v6.0 `knowledge_store.py` 为命名空间隔离的本地关键词检索（向量 RAG 的轻量降级实现），同义表述可能漏命中；v6.4 已补齐 tracked 去重接口（`augment_prompt_tracked`），但业务检索仍只走 `ResumeRetriever` 一线，知识库注入暂无生产调用方 | 接入职业规划/出题的 Prompt 增强；知识规模大时升级向量索引 |
| **next_action 依赖模型自觉** | v6.0 三态推进决策采信模型声明，模型误判"回答合格"时可能少追问；已用"回答过短仍强制追问"硬兜底 + 未声明时回退阈值规则，且追问次数上限不受影响 | 用真实面试样本统计 next_action 与人工判断的一致率后再决定是否提升模型话语权 |
| **~~参考答案背诵面板未渲染~~（v8.16 已修）** | `detailed_qa`（逐题改写答案/背诵材料）此前仅进 Markdown 复盘导出，报告 Tab 只有「✍️ 含改写示范」徽标没有答案正文。v8.16 在报告 Tab 每题卡片新增可展开的"📖 参考答案（背诵材料）"（`<details>` 默认收起：改写答案 + 改写要点，按题干从 `detailed_qa` 映射，同题干取首条） | 学习材料仅存在于本人报告视图（v7.5 分享页已删除，无对外输出路径）；Markdown 导出渲染不变 |
| **市场基准数据来源（学术诚信披露）** | Gap 分析的"市场基准参照"数据来自本人此前已完成并提交的采集项目（job-crawler）的 `data.db`，经 importer + store 导入 `market.db`，**本次仅做管道整合、不含数据采集工作量** | 若评审基于"本次周期实际产出"，可评估替换为小样本人工整理/公开数据集 |
| **权重注入 prompt 因果未验证** | Diagnostician prompt 中的权重真正生效处在 `weighted_score()` 加权平均；prompt 是否改变模型打分分布未经 A/B 验证（已有 prompt 已改为中性诚实表述） | 做"有无权重说明文字"的 A/B 对照实验，量化影响 |
| **LLM 权重稳定性未测** | `analyze_jd_weights()` 用 LLM 判 JD 权重，`temperature=0.2` 非完全确定，"千岗千面"卖点的同-JD 权重方差从未测过 | 固定 JD 反复采样统计权重方差，给出稳定性区间 |
| **输出检测仅监控不阻断** | `security.check_output()` 检测到泄漏仅记日志、不拦截、不脱敏，泄漏内容原样返回前端，属可观测性而非输出安全边界 | 需要时做输出脱敏/阻断（产品化阶段事项） |
| **职业规划路径未经验证** | v3.2 的路径推理为单次 LLM 生成，阶段划分/顺序/里程碑合理性未做 A/B 或专家校验；LLM 失败时走启发式三段式兜底 | 用真实职业样本做专家评审；将"路径可行性"纳入黄金样本回归评测 |
| **档案「待提升项」沿用全局薄弱点（v8.0 登记）** | `weakness_memory` 以 dimension 为主键、**全局无归属维度**（v6.3 设计），在单用户本地工具下即为本机唯一使用者的薄弱点画像，无"多用户互相可见"问题（v8.3 认证下线后该局限自动消解，无需再补 owner_id） | 若未来重建多用户认证，应按 PRAGMA + ALTER 范式给 weakness_memory 补归属列 |
| **守护机制的"有效窗口"很短（v8.10 登记，DC-11）** | v3.2~v8.9 期间 `run.py lint` 与 CI 的契约步**从不执行检查**（`python -m importlinter.cli lint` 无 `__main__` 守卫，恒 0 退出），分层"被强制"这一说法在效果上不成立；同期 `parse_pdf` 依赖未声明的 PyPDF2 而唯一断言是 `isinstance(result, str)`（永不可能红）。两者都是"绿灯没有信息量"，不是缺功能 | 已加反向自测（`test_layering_gate` / `test_dependencies` / `test_web_research::TestNoEventLoopBlocking`）：用已知坏样本证明门禁会变红。后续任何新门禁都应照此配一条自测；更彻底的做法是把 CI 步骤换成 `lint-imports` 直调并加 `--strict` 生态工具 |
| **PDF 解析能力上限（v8.10 口径变更）** | 解析失败不再返回 `[PDF 解析失败: ...]` 占位文本（该文本非空 → 绕过"提取不到文本"判断 → 被当简历正文入库并注入出题 prompt，HTTP 仍 201），改为返回空串 + 路由 400。这不提升解析能力：扫描版/图片型/加密 PDF 与复杂排版仍走 400（pdfplumber 无 OCR） | 需要支持扫描件时引入 OCR（如 PaddleOCR）或提示用户改用文本型 PDF；400 响应体可回传"未提取到文本"的原因码 |
| **证据引用可核但不阻断（v8.10 起可观测；v8.14 补全历史口径；v8.16 报告页渲染）** | 模型输出的 `quote` 现与候选人原回答做字面比对（空白归一 + 省略号分段全命中），不匹配标 `quote_verified=false` 并灰显展示，**不删除引用**。可核率两个口径并列：`/api/health` 的 `quote_stats` 进程内累计（重启归零）+ `quote_stats.all_time`（v8.14，报告 `qa_breakdown[].dimension_details` 落库后反查的全历史口径，老报告无该字段不进分母）；v8.16 报告 Tab 逐题渲染引用证据（未核实灰显加警示边） | 对不可核引用计入诊断置信度折扣（评分行为变更，未做） |
| **LLM 超时为统一上限（v8.10 新增；v8.15 起可按任务分级）** | `LLM_TIMEOUT`（默认 60s）对同步/异步/流式与全部 fallback 候选一致生效，此前不传该参数落到 SDK 默认 600s——一次挂起可把面试主循环钉死十分钟，且 SDK 只在超时/报错后才换候选，等于降级链一并失效。v8.15 起 `LLM_TASK_TIMEOUTS`（如 `{"report":180,"career":180}`）可按任务放宽，经每次 `create()` 的按请求参数下发；未配置任务沿用全局值 | WS 侧"单轮总预算"仍未做——它约束的是一轮对话中多次模型往返的累计时长，与本轮的单请求超时是两层，需独立设计 |
| **~~WS 突然断开会泄漏一条 SQLite 连接~~（v8.11 定位 → v8.12 已修）** | 根因比 v8.11 的假设更深一层：anyio 的 CancelScope 取消后，作用域内任务的**每个 await 都会被立即再次取消**，取消路径上 `finally: await db.close()` 永远完不成——连接带着在途 future 被遗留，测试 portal 循环一关，aiosqlite worker 线程向已关闭 loop 调度回调 → 线程未捕获异常（即那条 ~1/4 全量的 flaky；落点随时序漂移，v8.11 记的 TestPingPong 只是巧合）。v8.12 以取消安全的连接子类修复（`Task.cancelling() > 0` 时同步 `stop()+join`，机制详见 CHANGELOG v8.12）；同根的"异常分支不落终态"（现以 status=error 落库）与"`active_sessions` 无 TTL"（register/unregister/sweep 三件套）一并解决 | `_CancelSafeConnection` 的 join 依赖 aiosqlite 的 `_thread` 内部属性（已做 getattr 防御，缺失时退化为仅 stop()）；aiosqlite 跨版本升级后应回归：`pytest -q -W error::pytest.PytestUnhandledThreadExceptionWarning`（CI 已固化此门禁） |
| **~~依赖"冻结"只挡 PR，不挡首次安装~~（v8.10.1 发现 → v8.12/v8.13 已修）** | v8.8 以 `dependabot.ignore: semver-major` 冻结 openai 跨 major，但 requirements 只写下限本身允许任意高版本——实测干净环境解析到 openai 3.x 而本机 dev 2.x，"装到什么版本"每天在漂。v8.12 给 openai 加显式上限（`>=1.109.1,<4`）；v8.13 引入 `constraints.txt`（62 项 `==` 钉版含全部传递依赖）+ CI 安装步带 `-c` 并 `pip freeze` 记录实际解析 + 两条门禁（声明的包必须被钉住 / 必须精确钉版，删除钉版即红已实测）；dev 环境已对齐锁定版本，"本机绿"与"干净环境绿"自此是同一版本组合的绿 | 升级依赖走 constraints.txt 文件头的五步流程（改下限 → 重解析 → 重生成 → 干净环境全量 → CHANGELOG 记录）；前端已有 package-lock.json 无需此套；跨 major 仍由 dependabot PR + 人工评审 |

> **关键结论**："1134 个用例通过（另有 1 条真实模型抽检默认跳过，共 1135 条）"不等于"核心功能被验证"。核心诊断质量依赖 LLM，测试套件验证的是**工程正确性**；v7.0.3 起新增**黄金样本回归**与 **live-LLM 抽检**（`tests/test_diagnosis_golden.py`），首次把**诊断有效性**纳入可观测范围。
>
> 还有一条 v8.10 学到的：**门禁的绿也要能被证伪**。v3.2~v8.9 期间 `run.py lint` 从不执行检查（详见 CHARTER DC-11），所以"契约通过"当时不携带信息；现在 `tests/test_layering_gate.py` 会先用一个故意越层的样本证明门禁会变红。
