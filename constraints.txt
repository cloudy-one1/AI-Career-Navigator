# ============================================================
# 依赖锁定（constraints.txt，v8.13 引入）
#
# 为什么存在：requirements.txt 只写下限（>=），"装到什么版本"此前每天在漂——
# v8.10.1 实测干净环境解析到 openai 3.x 而本机 dev 是 2.x，兼容性靠运气不是机制。
# 本文件把"当前被验证过的版本组合"钉成被评审过的决定。
#
# 用法：pip install -r requirements.txt -c constraints.txt
#   -c 只约束解析、不强制安装（未列入 requirements 的传递依赖不会被装上）；
#   与 requirements.txt 的差集是纯传递依赖，升级 requirements 后本文件随之更新。
#
# 升级流程（改版本 = 被评审的决定，不允许"顺手漂"）：
#   1. 改 requirements.txt 的下限；
#   2. 干净 venv 只装 requirements.txt 重新解析；
#   3. 用新的解析结果整体重生成本文件；
#   4. 干净 venv 按 requirements + constraints 复装，跑全量 pytest + run.py lint；
#   5. CHANGELOG 记录本轮解析到的关键版本。
# 前端已有 package-lock.json（npm ci），本文件只管 Python 侧。
# ============================================================
